METHOD / TRANSPARENCY BY DESIGN

A test should be
easy to question.

A clear method helps readers see what a result means, how it was produced, and what would be needed to make a stronger claim.

01

Define the question.

Choose a test that maps to a practical use. Set scope, relevant product revision, host system, supported modes, procedure, sample size, and stop criteria before measurements begin.

BEFORE THE TEST
02

Record the setup.

Capture exact configurations and software versions when available. Identify owner-supplied information separately from contemporaneous evidence. Leave unknown session details marked pending.

AT THE TEST BENCH
03

Keep original observations.

Retain source CSVs and notes; report timestamps, sample counts, missing values, failures, interruptions, and meaningful deviations. Preserve negatives rather than silently repeating them away.

DURING THE TEST
04

Match conclusions to evidence.

Separate sensor data, operator reports, subjective impressions, and interpretation. A short capture stays short. Telemetry is not throughput; a template is not a product review.

IN THE REPORT
05

Disclose the relationship.

State whether hardware was owned, purchased, gifted, discounted, or loaned, and disclose payment, affiliate terms, return conditions, manufacturer involvement, and material corrections.

BEFORE PUBLICATION

MEASUREMENT NOTES

Numbers need their units
and their context.

The existing GPU logger queries NVIDIA telemetry and writes CSV plus run metadata. Analysis can be reproduced offline and does not query the GPU.

Sample statistics

Means are arithmetic averages of valid samples; minima and maxima are sampled points. Polling jitter and gaps are disclosed. Time-weighted averages are not implied.

GPU telemetry

Driver-reported power is not calibrated wall power. VRAM is reported in MiB. Sample polling can miss transients; it cannot establish acoustic output, thermals, or throttling without those measurements.

Reliability

State the number of attempts and duration. A short compatibility check cannot prove long-term reliability. Report recovery steps and unresolved failures.

Safety and privacy

No settings are changed as part of monitoring. Obtain owner approval before new workloads, installs, firmware changes, or destructive steps. Review exports for private data.
